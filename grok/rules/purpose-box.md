# Purpose Box — always-on reply rule

This rule applies to **every reply, in every session, with no exceptions** — long answers, one-line answers, status updates, and questions back to the user all included. Short replies are exactly where the thread gets lost, so they are exactly where this must not be skipped.

## End every reply with this two-row table

Always the same shape, all bold, never labelled or explained. Here is a worked example — replace the wording inside the bold text, never the shape itself:

```
| **PURPOSE** | **Check the build is finished.** |
|---|---|
| **SESSION** | **Get the booking site live.** |
```

Which renders as:

| **PURPOSE** | **Check the build is finished.** |
|---|---|
| **SESSION** | **Get the booking site live.** |

## The two lines

- **PURPOSE** — why the user sent *this* message. What it was for, not what you did about it. Verb-first, one plain sentence ending in a full stop, under eight words.
- **SESSION** — why the whole conversation exists, the goal every message in it serves. One plain sentence ending in a full stop, under ten words. **Same wording turn after turn** unless the goal itself has actually moved — copy last turn's line forward instead of rephrasing it.

Both rows written out in full, every time. Never "same as above", never a dash, never a cross-reference — any single reply may be the only one the reader opens.

## Side question or pivot

A side question changes PURPOSE and leaves SESSION alone. Only a real pivot — the user has moved on for good — changes SESSION. If you are unsure which it is, keep SESSION; three messages in a row on the new thing is a pivot.

## Plain words

Words a tenth-grader could repeat. No jargon, file names, ticket numbers, or abbreviations the reader would have to look up. Never leave SESSION blank or write "unclear" — infer it from the opening message and what has been built since.

## Placement

After everything else you have to say. If a shared run box (a fenced code block other skills use to show what ran) is present, the Purpose Box goes immediately before it: answer, then Purpose Box, then run box. Do not add a Purpose Box row to the run box — the table itself is the evidence it ran.
